要了解DNS解析过程首先要了解域名的层级结构

```shell
主机名.次级域名.顶级域名.根域名
# 即
host.sld.tld.root
```

域名的四个层级，以 `www.xiaomingyang.com.` 为例，从右往左（末尾的点是根域名）：

```shell
www.xiaomingyang.com.
│   │               │ └── 根域名(root)：末尾的点，整个DNS层级的最顶端
│   │           └─────── 顶级域名(TLD)：.com 是通用顶级域名，.cn/.us 是国家顶级域名
│   └──────────────────── 次级域名(SLD)：注册得到的域名，xiaomingyang.com
└───────────────────────── 主机名(host)：www、mail 等，查询域名本身时没有这一级
```

根域名(root)在最顶端，根区由 ICANN 维护，共 13 组根服务器，命名为 a~m（anycast 部署在全球，实际节点有上千个）。

DNS大致解析过程

```shell
从"根域名服务器"查到"顶级域名服务器"的NS记录和A记录（IP地址）

从"顶级域名服务器"查到"次级域名服务器"的NS记录和A记录（IP地址）

从"次级域名服务器"查出"主机名"的IP地址
```

DNS的查询有两种方式：

- **递归查询**：客户端问本地DNS"直接给我答案"，本地DNS替它跑完整个流程
- **迭代查询**：本地DNS逐级去问，每一级只回答"下一级去问谁"（referral），并附上下一级的NS记录；NS记录里附带的A记录叫胶水记录(glue record)，用来直接解析下一级服务器的IP

`dig` 命令的 `+trace` 参数可以显示DNS的整个分级查询过程

```shell
dig +trace xiaomingyang.com
```

输出中 4 个 `Received` 块正好对应迭代查询的 4 跳：

```shell
114.114.114.114        本地DNS，返回 13 组根服务器列表
d.root-servers.net     根服务器，返回 .com 的 gTLD 服务器列表
h.gtld-servers.net     .com gTLD 服务器，返回 xiaomingyang.com 的 NS
f1g1ns1.dnspod.net     权威DNS（DNSPod），返回 A 记录
```

每一级都会按 TTL 缓存查询结果，所以日常的大多数查询在本地DNS就解决了，根本到不了根服务器。
